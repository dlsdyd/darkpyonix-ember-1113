# 모듈 목록 (Phase 3)

> 기준: 크레이트(`ember/<crate>/`) 단위가 기본이다. 3,000줄 규칙을 그대로 쓰면 모듈이 80개를 넘어 읽기 어려워지므로, 큰 크레이트는 하위 시스템 단위(대략 3천~1만5천 줄)로 나눴다. 테스트 디렉터리(`ember/*/tests/`)는 크레이트별로 흩지 않고 `tests` 모듈 하나로 묶었다. 파일 안의 `#[cfg(test)] mod tests`는 그 파일의 모듈에 속한다.
> 할당 규칙(위에서부터 처음 맞는 것): `.scratch/analysis/modules.py`. 모든 분석 대상 파일은 정확히 한 모듈에 속한다.
> 분석 순서: 의존 그래프의 잎(전송, 공용 크레이트)에서 시작해 server, app 순서로 올라간다. `ember/app/src/ui/cr/`는 `ui/`의 Dioxus 화면을 compose-rust로 옮기는 중인 사본이다 (`ember/app/src/ui/cr/mod.rs:1-3`, #220).
